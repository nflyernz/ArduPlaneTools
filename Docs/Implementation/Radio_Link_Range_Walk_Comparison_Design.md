# Radio Link Range-Walk Comparison — design proposal

**Status:** Research/design only, 2026-10-10. Local APT source on `radio-link-compatibility-audit` at `e38717a` is the implementation basis. The October 8 EdgeTX CSV is private exploratory evidence, not a CI fixture. Automatic landmark detection and RF comparison have **not** been implemented or field-validated.

## Purpose and scenario

Compare two or more repeated physical walks on the same route while changing a receiver antenna position or orientation (for example, “Original antenna”, “Vertical”, “Under wing”). The useful result is whether marginal *observed* link quality improves before any Plane failsafe. A walk with zero failsafes still has value. The operator pauses at the same ordered landmarks, holds full elevator-down for about two seconds, releases, then continues. The local radio log supplies those markers even if the aircraft receives nothing at that moment. Corresponding landmarks identify **sections**, not equal metre-by-metre positions or distances. The aircraft BIN, if available, supplies a separate Plane-assessed RC-invalid/failsafe result.

## Verified local capability and missing pieces

[`read_edgetx_csv`](../../Scripts/core/edgetx.py) requires unique `Date`, `Time`, `RQly(%)`, `1RSS(dB)`, `2RSS(dB)`, `RSNR(dB)`, `RFMD`, `TPWR(mW)` headers, validates rows and increasing radio-local timestamps, and returns `EdgeTxSession` with raw numeric fields, `active`/`partial`/`unavailable`/`ambiguous` availability and runs. It optionally reads `GPS`, `FM`, `TRSS(dB)`, `TQly(%)`, `TSNR(dB)`. The parser does **not** retain `Ele`, walk labels, landmark markers or sections; its availability interpretation is validated for the controlled ELRS/CRSF schema, not arbitrary radios. [`analyse_edgetx`](../../Scripts/core/edgetx.py) is an optional overlay on one BIN Radio Link result: aircraft GPS may support pairing/coarse alignment, while episode numeric RF requires a bounded clock offset and RF sample age. [`RadioLinkDetector`](../../Scripts/core/radio_link.py) remains the authority for Plane episodes. [`log_selector`](../../Scripts/analyses/log_selector.py) selects BINs, not an arbitrary labelled set of CSVs. Current presentation offers one BIN plus optional one CSV. Portable [`EdgeTX tests`](../../Scripts/test_edgetx_radio_link.py) cover parsing and conservative overlay, not range walks.

The available `Logs/Piper Cub-2026-10-08-112115.csv` has `Ele` plus the required ELRS columns. Its 4,990 rows span 498.95 s; 4,988 of 4,989 adjacent gaps are 0.1 s (one is 0.15 s). `Ele` ranges −2 to 6 and is mostly 1–3, so this file **does not verify** full-down sign, amplitude or a deliberate two-second marker. It demonstrates header and row cadence only. EdgeTX's [CSV writer](https://github.com/EdgeTX/edgetx/blob/main/radio/src/logs.cpp#L148-L204) labels main controls by canonical name; at each logging tick it writes the radio's [calibrated main-control value](https://github.com/EdgeTX/edgetx/blob/main/radio/src/logs.cpp#L308-L313) independently of received telemetry. EdgeTX [defines `Ele` as a canonical control](https://github.com/EdgeTX/edgetx/blob/main/docs/development/control-inputs.md#canonical-names). This supports a **transmitter-local marker candidate**, not an established sign or threshold on this radio. The local CSV's 0.1 s *row* spacing does not timestamp individual RF-sensor updates.

## Proposed landmark procedure and detector contract

Before each walk, start one fresh EdgeTX recording, check the intended model and consistent RF settings, establish link and logging, then use the same ordered landmark list. At each landmark stop, move the elevator stick deliberately to its full-down end for about two seconds, release fully to neutral, and continue. Do not depend on the receiver or aircraft seeing the command. Capture the antenna setup, TX power policy, ELRS band/firmware and RF mode/packet-rate configuration when known; label the file. A brief stationary calibration at the start should record **neutral → full down → neutral → full up → neutral** with spoken or written times. This determines which `Ele` sign and magnitude actually correspond to down and gives an opposite-direction rejection example. Keep normal route stick handling as quiet as practical; a routine elevator movement is not inherently a marker.

**Candidate only, pending calibration:** read the unique `Ele` column alongside CSV row timestamps without passing it through RF availability gating. Infer down direction and endpoint band from the calibration, never from an assumed sign; reject missing, duplicated, nonnumeric or uncalibrated `Ele`. Find contiguous near-endpoint down runs with a return to a calibrated neutral band, allowing only short gaps justified by measured row cadence. Require an approximately two-second hold and an explicit release; choose hold-duration and sample-gap tolerances from the calibration rather than hard-coding them from the current 0.1 s example. Merge adjacent detections separated by a short bounce/retrigger interval, and require a clear new neutral-to-down transition for the next marker. Reject or flag ambiguous short movements, overly long holds, partial start/end holds, saturation in both directions, repeated gestures at one site and wrong marker count/order. Show the candidate time interval, duration and confidence/ambiguity reason for user confirmation. If the data cannot distinguish a deliberate hold from ordinary control activity, use manually selected row times instead of silently assigning landmarks. A valid local `Ele` marker can coexist with `RQly`/`1RSS` unavailable; report RF missing for that section, not marker missing.

Optional `RCIN` can corroborate that the aircraft received a command *after* a separately supported BIN/CSV alignment and verified channel mapping. It cannot define or veto the transmitter-local marker; RF loss may remove exactly the aircraft record of interest. `CH2(us)` in a radio CSV is also a mixed channel output, not a substitute for checking the local `Ele` source and sign.

## RF measurement and provenance contract

| CSV evidence | Proposed meaning and boundary |
|---|---|
| `RQly(%)` | Receiver-reported uplink packet-quality observation returned to and logged by the transmitter. Analyse only rows the ELRS parser classifies as usable; distinguish observed 0 from all-zero unavailable placeholders. A CSV row is not proof that the value was freshly acquired on that tick. |
| `1RSS(dB)`, `2RSS(dB)`, `RSNR(dB)` | Receiver-side uplink RF observations carried back in telemetry. `1RSS`/`2RSS` header says dB, but ELRS values are reported in dBm; negative/zero availability rules remain schema-specific. Do not equate SNR, quality and strength or infer receiver sensitivity margin. |
| `TRSS(dB)`, `TQly(%)`, `TSNR(dB)` | Optional transmitter-observed downlink fields; show separately if used, never mix with receiver uplink distribution. |
| `TPWR(mW)`, `RFMD` | Radio-logged status observations. `TPWR` is reported mW, not measured radiated power or proof of a fixed/dynamic-power setting. `RFMD` is an index, **not an independently verified packet rate**; mapping needs known ELRS band/version/configuration. |
| `Ele` | Locally recorded control input for landmarks. It is not RF telemetry and is not proof the aircraft received a packet. |
| CSV availability and gaps | Parser-derived row/run evidence, not a physical RF-loss timestamp. A full all-zero placeholder or missing RF reading is never a measured 0%/0 dBm minimum. A held nonzero sensor can be old; no per-sensor acquisition timestamp or general freshness bound exists in the CSV. |

Keep every value's source (`EdgeTX CSV`, field, file/row time, availability rule) explicit. Firmware/protocol differences require separate interpretation; the [receiver compatibility audit](Radio_Link_Protocol_Compatibility_Audit.md) does not justify aliasing FrSky RSSI/VFR into ELRS fields. For packet rate, record user-supplied configured rate or verified protocol mapping with provenance; otherwise print `unknown (RFMD index n observed)`. See [ELRS signal-health definitions](https://www.expresslrs.org/info/signal-health/) for why mode interpretation is configuration dependent.

## Section-level comparison proposal

Represent each walk as a labelled CSV source plus ordered confirmed marker intervals. Section 0 may be “start → landmark 1” only when a comparable start is explicitly defined; otherwise compare only landmark 1→2, 2→3, etc. Use release/end of the first hold to onset of the next hold, excluding gesture/stop windows from moving-section statistics. Markers identify ordered route segments, not shared positions or equal speeds. A section missing either boundary is **incomplete**; do not shift later markers by ordinal guesswork. Show both raw row count and elapsed covered interval, usable-observation count/proportion per metric, unavailable/partial/ambiguous counts and gap runs, with a warning that row counts can overrepresent held values and interval durations have row-cadence uncertainty.

For comparable ELRS sessions, report `RQly` median and lower percentile (for example, 10th), `1RSS` and `RSNR` median/lower percentile, and observed min/max as context; show units, counts and the percentile convention. Report sequences/clusters of observed marginal values and their sampled spans **descriptively**, without inventing a universal poor-link cutoff. A user-selected threshold could later define “time below X” after field validation; v1 need not provide one. If a defensible fixed threshold is not established, avoid a poor-quality percentage, health score or winner label. Present side-by-side per-section distributions and coverage so a user can judge improvement and missingness. A lower percentile reflects logged samples, not an independent packet distribution or exact time-weighted RF state. A long unavailable run means insufficient observations, not good or bad measured RF. If a section has too few usable observations, show counts/coverage and `insufficient RF observations` instead of a numeric comparison.

Display each walk's antenna configuration, TX power report/configuration, RFMD index and independently known packet rate/version/band. If settings differ or change within a section, visibly qualify the comparison and split/flag the setting transition; do not rank antenna effects as isolated. Compare like-for-like metrics only under the same validated radio schema. Do not infer distance from time, section number or transmitter GPS without an explicit validated distance model.

## Missing evidence, optional BIN and user workflow

A walk with missing/duplicate `Ele`, unconfirmed sign, marker count mismatch, out-of-order markers, interrupted logging or partial route remains visible with a specific reason; compare only sections bounded by confirmed corresponding landmarks. A telemetry gap can overlap an intact locally recorded marker. Report absent RF samples and coverage separately from measured low values. Never infer a receiver failsafe or a physical RF outage from a CSV gap alone.

Minimal on-demand CLI proposal: select **two or more CSV paths** (new CSV-capable multi-file selection, since the shared selector is BIN-specific); enter descriptive labels and an ordered landmark list; inspect/confirm calibration and detected marker intervals or provide manual marker times; receive a side-by-side section table and per-walk evidence notes. No persistent database, background scan, GUI, extra channel or GPS is needed. Keep CSV content identity and path/label separate; byte-identical copies should be noted as duplicates, not independent walks. User labels describe antenna setups, not an inferred physical configuration.

Optionally attach one corresponding ArduPlane BIN per walk. Use existing `RadioLinkDetector` and [`analyse_edgetx`](../../Scripts/core/edgetx.py) pairing/alignment decisions where their evidence applies; a user-selected pair is not automatically precisely aligned. Aircraft GPS/CSV landmarks can provide coarse context, while numeric episode RF remains withheld without bounded offset and sensor age. BIN episodes remain authoritative for Plane response, never created, merged, retimed or cleared by CSV markers/gaps. A marker on the radio and a corresponding `RCIN` observation may corroborate alignment only if reception, mapping and latency are established; a missing `RCIN` echo is not a failed marker.

## Portable tests, first validation and phases

Synthetic tests should cover CSV column positions/duplicates, calibrated normal and reversed elevator sign, neutral/down/up runs, two-second holds with measured-cadence jitter, short ordinary movements, release and bounce suppression, incomplete/log-boundary holds, missing/multiple/out-of-order markers, markers inside RF-unavailable runs, differing walk speeds, per-section metric counts/percentiles and excluded placeholders, long held values, no-event BIN, ambiguous BIN/CSV alignment, and settings differences. Test the pure marker/section projection with small generated CSVs; private logs are development evidence only, never required CI fixtures.

**Smallest real-world gate before automatic detection:** at a stationary prop-off bench, start one new EdgeTX CSV and record clock times for neutral→full down→neutral→full up→neutral, then two deliberate approximately two-second down holds separated by release and one ordinary short down motion. Interrupt receiver telemetry during one hold while the radio continues logging. Inspect `Ele` header/sign/endpoint/row cadence, marker visibility, release separation and RF fields during the interruption. The existing October 8 file cannot answer these questions. A short repeat with actual walking stick motion tests false positives before using automatic markers on comparative walks. No change to the controlled aircraft failsafe procedure is implied.

Proposed phases: **(1)** validate the radio-local marker contract; **(2)** add CSV-only multi-walk ingest, user labels/manual-confirmed markers, section projection and measured-distribution/coverage report; **(3)** enable automatic markers once the field gate and synthetic tests pass; **(4)** optionally attach BIN response and conservative pairing. Flight Event History is a separate track in the [architecture audit](Multi_Log_History_Architecture_Audit.md).

Open decisions after validation: exact calibrated endpoint/neutral bands and duration tolerance; how many usable RF observations merit a numeric section comparison; whether any field-specific sensor-age bound can be established; how to display changing dynamic TX power; whether packet rate can be independently recorded or mapped for the tested firmware; and whether explicit start/end gestures are needed for comparing the first/last route legs. None justifies inventing a failsafe threshold, range estimate, or overall link-health score now.
